Roll Filter Popover – ASCII Wireframe
=====================================

Context: the Rule Tester roll filter trades the ≥ / = / ≤ comparators for a
compact “pick the roll counts you care about” UI. Each row exposes the six roll
counts (`Ø`, `1`, `2`, `3`, `4`, `5`) as toggleable badges so users can pick any
number of discrete values (e.g., {2, 4, 5}). The backend stores those sets
directly, so the filter semantics match what the UI renders.

Legend
------
- `[X]` close button supplied by `ContextMenuPaper`
- `●` = selected roll count, `○` = unselected
- `[All]` text button = select all roll counts for that row (shown left of the label)
- `[⊗]` = the shared clear icon button (renders to the right of the badge rail)
- Stat summaries show braces (`SPD {2,4}`) in the footer/aria copy instead of inline chips
- Wildcard row always applies to “Any stat”; per-stat rows remain glyph-only stats

Key behavioral notes
--------------------
1. Expressiveness mirrors discrete sets; predicates test membership directly (no comparators).
2. Wildcard row always targets “any stat.” Per-stat rows manage stat-specific combos. Users pick
   one approach at a time; toggling one section clears the other.
3. Select-all buttons sit to the left of each row label (matching the builder’s substat menu).
   The clear icon button lives to the right of the roll badges, keeping “controls → value → clear”
   consistent with other builder surfaces.
4. Non-glyphable stats stay hidden; every glyphable stat is always visible. Summary copy mirrors
   the `{…}` notation so users understand they’re selecting exact counts rather than ranges.
