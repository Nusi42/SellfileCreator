# Application Behavior

This document captures runtime behavior, builder interactions, and user-facing workflows.

## Slot Constraints

- Source of truth: `src/lib/types.ts` exports slot constraints as `ALLOWED_MAIN_BY_SLOT` and `ALLOWED_SUB_BY_SLOT` using `StatVariant` constants (no inline bit-math).
- Helpers: `slotSupportsMain`, `slotSupportsSub`, `anySelectedSlotSupportsMain`, `anySelectedSlotSupportsAllSubstats` centralize feasibility checks.
- Builder integration:
  - `hsfBuilder.ts` calls `anySelectedSlotSupportsMain` before emitting rules so mains that cannot exist on the selected slots are skipped.
  - Substat combinations are not pruned by slot in the builder; this is intentional so RSL can still match rules against Any-slot exports while the UI (Rule Tester, warnings) surfaces slot feasibility using the shared helpers.
- Rationale: Keeps domain facts in one place so both builder and UI share the same slot feasibility rules and prevents impossible main stats when slots are restricted.

## Builder Outputs and Normalization

- Builder outputs (HSF):
  - Always include `Rank`, `Rarity`, and `Faction` (0 = Any).
  - Always include `ArtifactSet` and `ArtifactType` (emit `[]` when unfiltered).
  - Export order emits `ArtifactSet` (before `ArtifactType`) directly ahead of `Rank` so the legacy `.hsf` diffs stay stable; substat tuples always declare `NotAvailable` before `Condition`.
  - Emits rules only for milestone levels within an explicit window `[minLevel..maxLevel]` (inclusive). Levels are 0/4/8/12/16.
  - Levels where the selected `minCount` substats cannot physically exist for the item’s rarity (e.g., Epic has only 3 substats before +16) are skipped.
  - `Substats` always contains 4 entries (selected + padded).
- HSFC normalize: `normalizeConfig(input: unknown)` builds a `BuilderConfig` by assembling a base object and conditionally adding optional fields; never assigns `undefined` to optional keys. When `minLevel`/`maxLevel` fields are omitted, the parser defaults the window to `[0..16]` before returning the config.
- Aggregate min target: `minRequiredRolls` always applies across the selected substats in a rule. Use `lockedMinRequiredRolls` to enforce an additional locked-only floor (ignored when no substats are locked). When the locked floor is the only aggregate requirement the builder scopes the aggregate sum to just those locked stats; once any global floor exists, both floors apply — the global sum spans every selected stat while the locked sum only considers the locked subset. Legacy HSFC files that stored `minRollsTarget: 'Locked'` or `substatMinTarget` are upgraded on import by moving the manual aggregate floor into `lockedMinRequiredRolls`; when locked substats exist the importer now drops the manual total so pure locked-only configs stay faithful to their original scope.
- Shared normalisation helpers live in `src/lib/configNormalization.ts`; the builder UI, HSFC IO, and merge path import them so feature rules (keep-mode fallback, auto flex eligibility, rarity supplements, level window guards, etc.) stay consistent everywhere.
- Implementation note: `src/lib/hsfBuilder.ts` now focuses on orchestration while the strongly-typed schema lives in `src/lib/hsfBuilder/types.ts`, roll-target normalization resides in `src/lib/hsfBuilder/targets.ts`, and the combination/permutation math is in `src/lib/hsfBuilder/combinatorics.ts`. Import from those helpers instead of re-implementing ad hoc copies.

## Preview Filters (RulesFilterPanel)

- View-only; export is not affected. State lives in `src/lib/rulesFilter.ts`.
- Persistence is mode-aware: Sellfile Preview and Rule Tester each remember whether the drawer was open, which chips were selected, and which sections were collapsed. Switching modes rehydrates the matching snapshot, and both sets of values persist across sessions.
- Right-click the filter button to open the context menu (same hint overlay as the Export button). The menu includes a persistent “Sync filters between views” checkbox that forces both preview modes to share one filter state, plus a `Reset Filters` action that clears both modes back to factory defaults.
- Shortcut: `Ctrl+F` (`Cmd+F` on macOS) opens the filter panel (when closed) and focuses the config-name input if it is present, mirroring the browser “Find” gesture without reusing the native overlay.
- AnyMode chips: `Show` (state `include`) keeps rules that don't specify a field, `Hide` removes them, `Only` shows only those rules.
- Substats support include + exclude in the same button grid:
  - Left click (from Off) toggles “must have”.
  - Right click (from Off) toggles “must not have” (rendered with a diagonal strike on the label).
  - Clicking any active state (left or right) clears back to Off (no cycling between include/exclude).
  - The persisted state stores exclusions in `filter.sub.notSelected` and filtering removes any rule/item that contains any excluded substat variant before evaluating the “must have” match policy.
- Sets
  - Metasets unroll into explicit set IDs before matching.
  - Match mode `Any`/`All` combines selected sets.
  - Final-sell remainder rows (marked internally) are excluded when any set is selected so results aren’t dominated by “All Currently Known”.
  - The Sets selector reuses `SetMenuSection` (icons/list) with metaset hover highlights and anchored placement consistent with the Builder.
- Config name regex: the optional field only appears when at least one config has a name or the user typed a query. Patterns reuse the builder's styling and accept case-insensitive regex; invalid input highlights the field but leaves other filters intact.
- Config buttons: the filter header always shows two controls. `Preview Configs` (the visibility toggle next to the config-name field) hides chips whose rules fail the active filters; it now defaults to off and `Reset filters` returns it to off. `Config Filter` gates the preview to the selected config chips: in Sellfile mode it’s a simple On/Off toggle, while Rule Tester mode expands it into a tri-state (`Off` → `First-Match` → `Any-Match`) so users can decide whether the imported gear requires the first matching config or any matching config. When no chips are selected the button still cycles but effectively behaves like `Off`, and `Reset filters` always returns it to `Off`.
- Collapsible sections keep a builder-style Clear icon next to their collapse toggle. The icon only appears when that section diverges from its defaults (including tester-only controls such as glyph chips or the level slider) and clicking it resets just that subset without touching the rest of the filters.
- When the preview switches to the Rule Tester grid, the `Rule` section becomes a tester result filter (Keep/Sell vs Matched/No Match) so the grid can be trimmed to only the desired outcomes, and the Any/Only chips for Slot/Rank/Rarity/Level hide because the gear queue always provides explicit values for those fields.
- Tester level slider: in Rule Tester mode the Level section replaces the milestone toggle grid with a compact dual-handle slider (0–16). The handles preserve the existing layout, persist with the rest of the filter state, and filter the gear entries by `artifact.exactLevel` when available (falling back to the milestone level when the exact value is missing). The Sellfile preview keeps the original +0/+4/+8/+12/+16 toggle buttons and their Any chip.
- In Rule Tester mode both `Configs` buttons remain visible: `Preview Configs` continues to control chip visibility, while `Config Filter` applies its tri-state filter to those gear entries only (`First-Match` keeps items whose first matching config is selected; `Any-Match` keeps items that matched any selected config, even if another config won first). `Reset filters` always turns `Preview Configs` back off and returns `Config Filter` to `Off`.
- Champion filter: when the queue includes gear equipped on champions (imported collections/vaults/inboxes), a searchable multi-select appears next to the Source buttons so the preview can be narrowed to those heroes’ items. Manually added gear ignores the selector and reappears once the chips are cleared.
- Tester roll filters: the tester view still adds a `Rolls` chip next to Substats, but the popover now mirrors the builder’s roll badges instead of comparators. Users either pick counts in the wildcard row (always scoped to “Any stat”) or configure individual stat rows—interacting with one section clears the other so the predicate stays unambiguous. The wildcard row starts empty (matching the chip’s `≥ 0` state) and only lights up once the user toggles badges; selecting every badge auto-collapses back to “≥ 0” so the chip and panel stay in sync. Each row shows the six roll badges (Ø–5) plus a Clear icon to the right of the badge rail (matching the builder’s substat menu). Per-stat rows enforce their own AND semantics, so they no longer modify the Substats picker or Match chip, and they render every rollable stat—including CR% and CDMG%—so testers can filter those substats directly. Summary text and the chip’s aria-label spell out the chosen sets (e.g., `Any rolls {2,4} • SPD {2,4} & ACC {1}`), and clearing the popover removes the filter entirely. When a user selects `5` rolls the matcher also treats Mythical pre-roll bonuses as the hidden fifth roll (the importer exposes them via `mythValue`), so Mythical four-roll substats still satisfy a `5`-roll requirement.
- Gear helpers now live in `src/hooks/useTesterItemsActions.ts`, which assigns deterministic ids, diffs Gear DB imports, and explains every step inline (per the orchestration commenting rules). The hook feeds App.tsx but keeps the signatures stable for future consumers.
- The tester pipeline logs `[tester-items] preview artifacts …` whenever `testerPreviewArtifacts` rebuilds and `[tester-items:restore] apply …` when autosave restores rehydrate items. These console stamps confirm when artifact queues are empty, how big the cache is, and whether autosave loads are retriggering Keep Unique detection loops.

The default pairing benchmarks `examples/example.hsfc` against `examples/251112_042110.db`, mirroring the heavy user scenario so regressions show up immediately.

The script echoes base matcher timings, Keep Unique candidate/detection durations, emitted Keep Unique rule counts, and the matcher timings after those rules are appended so optimizations can be compared without manual instrumentation.

  - Group buttons have explicit click handlers to toggle their member values reliably in multi-select.

- Spacing
  - Chip top margin is centralized: `FILTER_CHIP_TOP_MARGIN` in `src/lib/constants.ts`.
- Empty state
  - When filters hide all rows but rules exist, the table shows: “No RSL Helper Sellfile rules due to the filter.” (prop `emptyDueToFilter`).

## Autosave Restore Dialog

- Hook: `useAutosaveRestore` compares the stored HSFC payload (metasets, Substat Target Values, configs, Final Sell remainder, pinned note, filter state) against the current defaults. When anything differs and the README overlay isn’t blocking, it opens `RestoreAutosaveDialog`.
- Selective restore: Each section appears with its own checkbox (pre-selected). Applying the autosave only touches the checked sections, so builders can import metasets without overwriting configs, or pull in filters while leaving everything else intact.
- Persistent selections: The dialog persists checkbox states (per section) under `sellfileCreator.autosave.restoreSelection.v1`. The next time the prompt opens, it mirrors the user’s last choices for every available section instead of recomputing defaults, so power users can opt-out of sections once and keep that preference.
- Silent skip: When none of the sections above have anything to restore (e.g., the autosave only contained configs but the builder already has configs loaded), App immediately dismisses the dialog instead of flashing an empty shell. This mirrors the pre-dialog UX where no prompt appeared unless there was work to do.
- Filters: The dialog can now restore whether the panel was open, its chips, and collapsed sections; those values live alongside the HSFC payload in localStorage.
- Gear autosave: the tester queue (`AUTOSAVE_TESTER_KEY`) is decoded up front and offered as another checkbox. The saved list only replaces the current tester state when the box is checked; otherwise it stays in storage until selected (or overwritten by a newer autosave).
- Dismissal: Dismissing the dialog keeps the previous autosave in storage and delays builder autosave writes until the current session diverges, preventing accidental overwrites.
- Builder autosave payloads are now serialized off the main thread via `useDeferredHsfcPayload`. The first snapshot still runs synchronously so new sessions have data immediately, but every later change schedules `buildHsfcPayload` inside `requestIdleCallback` (with a `setTimeout` fallback) before `useAutosave` writes to `localStorage`, eliminating the 300–700 ms stall that used to fire on every config/metaset edit.

## Tuple Decoders (HSF → StatVariant)

- `mainToVariant` and `subToVariant` in `src/lib/types.ts` accept either boolean or 0/1 flags for flat/percent and normalize internally. This fixes flat mainstat filtering for inputs that use boolean flags.

  - Selecting a numeric value below the current lock clears the lock automatically. Selecting Auto or toggling the last numeric button always clears the lock as well.
  - HSFC imports/pastes normalize to these rules (0–5 only, at most one lock, GMRR strictly greater than the lock when both are present).
- `Reset Config` button:
  - Left-click: shows a localized confirmation dialog (`builderResetConfirmTitle`) and, when confirmed, resets to user defaults when present; otherwise resets to factory defaults. Buttons reuse shared `cancel`/`reset` catalog entries.
- Right-click (also available on `Insert as config` and `Apply as config`): opens a shared menu with Save local settings as user defaults, Reset to factory defaults, and toggle checkboxes.
  - User defaults are stored under `sellfileCreator.builder.userDefaults.v1`.
  - Auto reset after Insert: when enabled (default Off), the builder resets to defaults immediately after inserting a config (no confirmation dialog). State persists under `sellfileCreator.builder.autoResetAfterInsert.v1`. The toggle disables Auto apply when turned on.
  - Auto apply to selected config: when enabled (default Off), builder edits are applied to the current config automatically after ~400 ms of inactivity, and pending changes flush before switching configs. Preference key `sellfileCreator.builder.autoApplySelectedConfig.v1`. Enabling this toggle clears Auto reset so the behaviors remain mutually exclusive.
- Numeric spinner adornment: `NumberSpinnerAdornment` (`src/components/NumberSpinnerAdornment.tsx`) is the shared inline spinner used by Builder Roll Targets, the Substat Target Values dialog, and the Gear tab inside the Logic Hub dialog. It traps mouse down events to avoid blurring the active input and keeps the +/- hit targets identical across surfaces so accessibility and pointer behavior stay in sync.
- Config name editing keeps a local draft (`BuilderPanel`). Typing updates the draft only; the underlying `BuilderConfig.name` is updated on blur, on "Add as new/Insert after" and on "Save changes". This prevents in-progress edits from mutating chips/preview while still marking the builder dirty so the save CTA and nudges stay active. Clearing the name routes through the same commit helper.
- Undo/redo history: `useHsfcHistory` stores compressed snapshots that include both the HSFC payload and the live builder UI state (selection arrays, builder draft, multi-edit draft). Snapshots are keyed by a CRC of the HSFC-only signature so UI-only edits refresh the current entry instead of crowding the timeline. Controllers use `describeNextChange(descriptor | null)` to label the next entry, `captureSnapshotNow(descriptor)` to force an immediate append (e.g., before dropping a dirty draft on selection change), `resetHistory(..., { descriptor })` to seed the base entry, and `undoPreview`/`redoPreview` for tooltip metadata without decompressing snapshots.
- Undo/redo tooltips: `BuilderPanel` feeds those previews through `formatHistoryTooltipText` to render the descriptor title plus bullet-prefixed detail lines. When no descriptor is provided the tooltip falls back to the existing i18n copy (which still includes the localized shortcut hint) so localization coverage remains intact.
- Rule count chip: When the selected builder draft doesn't match a cached count, `BuilderPanel` asks the rule cache worker for totals via the `builderCount` message. The worker sums each config with `countRulesForConfigs()` and returns the per-config counts so the UI only adds them up on the main thread. The hook aborts stale requests and falls back to synchronous counting when Web Workers are unavailable (tests/SSR).
  - Extremely broad configs can explode into millions of permutations; counting stops once emission exceeds `RULE_COUNT_LIMIT` (~50k) so the UI stays responsive. When the limit trips the chip shows `≥ 50,000 rules` (localized) instead of blocking on an unbounded calculation.
  - Sellfile preview applies a global `TOTAL_RULE_COUNT_LIMIT` (150k) to the combined base HSF and custom builder output. When the cap is hit the offending configs are omitted from the preview/export (rule chips switch to `≥ 150,000`), while Final Sell remainder rows continue to render so the toggle always reflects user intent.
- Rule cache fast paths:
  - **Pure reorder / delete:** moving configs (drag, move up/down/top/bottom, “Paste after”) or deleting them no longer enqueues a warm-cache job. The cached rule batches are remapped in place (ConfigID annotations are updated) and the merged preview array is rebuilt from the cached base/custom/final-sell segments.
  - **Final Sell toggles:** flipping Final Sell options rebuilds only the final-sell tail locally. Base HSF rules and the cached custom batches remain intact; the worker is bypassed unless the underlying configs change.
  - **Worker still required:** inserting configs or applying the builder to multiple rows continues to flow through the worker. Earlier attempts to splice new batches locally regressed total-limit enforcement and metaset expansion, so the worker remains authoritative for those paths.
  - **Open issues:** the React dev warning _“Cannot update a component (App) while rendering a different component (AppStateProvider)”_ still fires when selection churn is heavy; the selection reducer still issues updates during render and needs a dedicated cleanup. Long lists also trigger `[Violation] Forced reflow` due to table virtualization—`HsfRulesTable` still requires follow-up profiling.
  - **Name-only edits:** when the rule fingerprint is unchanged and only config names differ, the preview rows update the stored `cfgName` labels in place and skip the worker entirely. Matches and detection remain intact because rule keys did not change.
  - **Restore safety:** autosave restores sometimes surface before deferred snapshots populate; the pipeline now falls back to immediate configs/metasets/substatTargets to avoid sending an empty payload (which previously yielded final-sell-only previews). A retry guard forces one full warm+match pass if configs exist but both base and custom rule counts come back zero.

### Config selection identity

- The chips panel and history stack track configs by object identity so reorders can map selections back onto the mutated array without diffing every field. Whenever an operation produces a new config (builder insert, duplicate, reorder-copy, clipboard paste, tutorial snapshot), call `cloneBuilderConfig` from `src/lib/multiEditDraft.ts` before writing it into `customCfgs`.
- Never push shared references into the configs array; identical payloads must still be distinct objects so selection updates don’t accidentally sweep every matching config. `cloneBuilderConfig` reuses the per-field clone helpers, so nested arrays (`substatsV`, `artifactSets`, etc.) are detached as well.
- When updating an existing config (e.g., “Apply Builder”), clone the builder draft once and reuse that object for both history descriptors and the `setCustomCfgs` call. This keeps undo/redo snapshots aligned with the chip identity the selection logic will reference after the update.

## Keep Uniques

### Logic Hub dialog integration

- The Logic Hub dialog is tabbed: `Final Sell` retains the legacy layout, while `Keep Uniques` renders the gear-combination editor plus mirrored tester grid inside the same shell dimensions (`min(960px, 100vw - 32px)` × `min(800px, 100vh - 48px)`).
- The active tab is tracked via `logicHubDialogTab` (autosave still reads the legacy `FinalSellDialogTab` field) so autosave, clipboard, and undo/redo restore whichever section (Final Sell, Gear, or Keep Uniques) the user left open; new sessions still default to `Final Sell`.
- Factory defaults seed two named rules: **Rare+ Accessories (5–6★)** is enabled and covers Rings/Amulets/Banners across every accessory-compatible set; **Utility Sets (5–6★)** is disabled and scopes to 6★ Legendary/Mythical Stun/Toxic/Cursed/Provoke/Destroy armor pieces.
- Factory default: a new session (or reset) preselects the standard 0/4/8/12 ranges but turns both Artifacts and Accessories off so nothing sells until the user opts in. The quick toggle flips both gear types on (and keeps the ranges) the first time Final Sell is enabled without manual selections.
- Keep Uniques exposes its own Reset button. It clears the combination list and disables the feature without touching Final Sell settings, so the two tabs never stomp each other’s defaults.
- When no gear entries are loaded the right column replaces the grid with a dashed empty-state card that repeats “Load a gear database to inspect at-risk combinations.” so the guidance appears exactly where results will eventually render; the rule sidebar intentionally suppresses a duplicate alert to keep that column focused on rule editing.

### Rule editing and detection

- The feature is opt-in: the top-level switch mirrors `keepUniquesEnabled` and gates both combination editing and detection. When off, detection state is cleared and an info alert explains that scans only run while the toggle is enabled.
- Rules live in the left column. The list uses the shared Gear selectors (`GearMainStatSelect`, `GearFactionSelect`) plus multi-select controls for Slots/Sets/Rank/Rarity/Main Stat so combination filters align with builder affordances. Empty selections map to “Any”, and the Sets dropdown reuses the builder/filter menu so metasets appear at the top (with their glyphs) and stay linked — renaming or editing a metaset updates every Keep Unique combination that references it automatically.
- Accessory/armor selections automatically constrain the set pool and determine whether the faction selector is shown; mixed selections fall back to “all sets”. Faction filters only apply when any accessory slot is included.
- Editing any field updates the builder store immediately. The `≥ required count` input clamps at `1+`, and each card exposes Enable/Disable plus Delete actions.
- Each rule also carries an optional name field directly beneath the enable toggle; names persist through autosave/HSFC and logging but do not affect detection or rule generation.
- The per-rule activation mode has three states: `Off` hides the combination entirely, `Protect existing` mirrors the classic behavior (only emit keep rows for matching gear that would otherwise be sold), and `Anticipate gaps` also emits placeholder keep rules whenever the current + sold totals cannot meet the quota so fresh drops stay protected until the inventory export catches up.
- Required Count is paired with scope chips beneath each picker (everything except `Rank` and `Rarity`). `Per slot`, `Per set`, `Per faction`, and `Per main stat` can be combined to multiply the quota for every Slot × Set × Faction × Main stat tuple; clearing every chip automatically falls back to the shared `Per rule` pool.
- The empty state promotes the `Add rule` CTA. Clicking it clones a combination seeded from the slot’s default main stat and set pool; additional clicks append new entries and focus them for editing.
- Detection (`collectKeepUniqueCandidates` + `computeKeepUniqueProtection`) only runs when preview gear is present, not building, and the match-freeze gate is released. We derive candidate artifacts by grouping the queue by slot + set + main stat + faction, replaying the merged rules without Keep Uniques, and keeping only the groups where every artifact would be sold. While a scan is pending the tab shows the warning alert; once complete, each rule keeps a single status chip that reports deficits, “covered elsewhere”, or “satisfied”. When detection emits a new snapshot we record its fingerprint and skip further scans until the worker acknowledges that exact signature, so autosave restores no longer retrigger the detection/warm-cache loop.
- The rule-cache worker now receives the full keep-unique payload (resolved rules + latest detection snapshot) so base rule generation, keep-rule injection, and match-index priming stay off the main thread even when Keep Unique mode is enabled. We record the detection fingerprint alongside each worker commit so the legacy merge effect can no-op when the worker already injected the scan results.
- Detection (`collectKeepUniqueCandidates` + `computeKeepUniqueProtection`) only runs when preview gear is present, not building, and the match-freeze gate is released. We derive candidate artifacts by grouping the queue by slot + set + main stat + faction, replaying the merged rules without Keep Uniques, and keeping only the groups where every artifact would be sold. While a scan is pending the tab shows the warning alert; once complete, each rule keeps a single status chip that reports deficits, “covered elsewhere”, or “satisfied”. When detection emits a new snapshot we record its fingerprint and skip further scans until the worker acknowledges that exact signature, so autosave restores no longer retrigger the detection/warm-cache loop.
- While detection is pending the tester grid keeps the previous Keep Unique matches rendered (only for rows whose last `match` came from `RULE_SOURCE_KEEP_UNIQUES`). We still recompute the base `match`/`baseMatch` metadata immediately, but the visible overlay sticks with the prior Keep Unique result so the cards no longer flicker empty → keep → empty → keep during the “apply keep rules” pass.
- Each gear row stores `baseMatch`, the first match result that excludes Keep Unique rules. Candidate detection reuses that snapshot instead of replaying `evaluateMatchesByConfig` for every row, so repeated scans and rule rebuilds no longer stall the UI on large datasets.
- Unique grouping runs even when Keep Uniques is disabled so the tester grid always surfaces the “at risk” combinations; disabling the feature still clears the detection snapshot and hides the deficit chip, but the item list stays populated for browsing.
- The grid header no longer shows a dedicated label; the Filter button anchors to the left while the right edge keeps the detection spinner (when scans are running) immediately before the selection-count chip so the “items” count stays right-aligned with the card column. Deficit summaries now live only inside the rule cards themselves.
- Alerts are contextual: disabled toggle, no gear loaded, or scan pending. Deficit summaries now surface directly on the rule cards, so the header remains dedicated to the filter control and selection count.
- Generated HSF keep rules are derived from the candidate artifacts instead of the combination filters. For every matching artifact we emit rules across its remaining level milestones (e.g., a +0 item exports 0/4/8/12/16), fix the slot/set/main stat/faction, and encode the current substats as `>=` thresholds so upgrades stay protected. Duplicate artifacts (across overlapping Keep Unique filters) are deduplicated by gear id and level milestone to keep the export minimal. When a rule runs in `Anticipate gaps` mode and detection still finds a deficit after counting the sold artifacts, we emit placeholder keep rules that pin the configured slot/set/main/faction filters at `Any level`; these placeholders disappear automatically once the quota is satisfied by real gear.
- Substat thresholds in injected Keep Unique rules mirror the tester’s `subValues` payload (base value plus rolls, excluding glyph bonuses). Using the same numbers keeps glyph-boosted items self-matching in the tester grid instead of over-constraining the generated HSF rows.
- The Keep Uniques grid only renders gear entries that qualify as “unique”: we group artifacts by slot + set + main stat + faction (armor treats faction as “Any”), replay the active HSF rules with Keep Unique combinations removed, and keep the group in view only when every artifact in that group would be sold under that trimmed ruleset. This makes the right-hand grid surface the at-risk combinations that still need protection rules.

- Jump-to-config wiring (`onJumpToRule`) mirrors the Rule Tester: clicking a matching-config chip in the grid still focuses the builder rule, even while the Keep Uniques tab is active.
- The tester-match worker is enabled again. Rule configurations (and the keep-unique injections that come back from the worker warm) are serialized via a fingerprint; whenever that fingerprint changes we rebuild the gear entries even if no artifacts changed so keep-only rules surface in the `match` column immediately. While the worker processes a build, the Keep Unique grid keeps rendering the last applied matches and only unfreezes cards once the worker commit includes the new ruleset and detection fingerprint.

### Sellfile preview integration

- Keep Unique injections land at the top of the Sellfile Preview table (ahead of base/custom/final rules) but are rendered as config-less rows so the “Cfg” column shows a hollow star icon instead of a numeric index. Clicking these rows no longer attempts to select a builder config because they omit ConfigID, keeping selection state clean.
- The preview scroll helper ignores those sentinel rows when it computes config spans, so jumping to a config or clicking a config chip always scrolls to the first matching builder row even if Keep Unique overrides are prepended to the list. Keep Unique rows still participate in focus jumps (Rule Tester → preview, Keep Unique grid chips → preview); when a jump targets one of these rules the preview scrolls directly to that row while leaving the builder selection untouched.

## Production-only Restrictions

- Native context menu and text selection are disabled globally in production builds to reduce accidental edits and copy noise. App context menus continue to work (native menu is prevented, propagation allowed).
- Allowed surfaces: Inputs, textareas, contenteditable nodes, and any element marked with `data-allow-select` / `data-allow-context`.
- Dev builds are unaffected; full selection and native context menu are available for debugging.

## File:// Launch Caveats

- If contributors open `index.html` directly from the filesystem (`file://`), expect limited or non-persistent storage in many browsers. LocalStorage writes used by autosave, color preferences, and table settings may not persist. Prefer `npm run dev` or `npm run preview` to serve over HTTP for reliable persistence.

## Clipboard and Context Menus

- The chip area always renders (min height) and exposes a context menu with “Select All”, “Copy all Configs”, and “Paste at End”. When empty, a centered hint invites right-click Paste.
- Chip context menu includes: Duplicate, Paste after, Move to Top/Up/Down/Bottom, Copy to Clipboard, Delete.
- Copy All uses `buildHsfcPayload` to copy the HSFC object (`Version`, `Metasets`, `Minima`/Substat Target Values, `Configs`, `FinalSellRemainder`, `SelectedConfigIndex`, and optional `Note`) so pastes preserve state.
- Paste accepts: single `BuilderConfig`, array of configs, or a full HSFC object in the readable schema. Legacy forms are not normalized.
- Clipboard fallback: in non-secure contexts (not HTTPS/localhost), programmatic clipboard is blocked, so the app opens a dialog with pre-selected text for manual copy/paste.

## Save/Load Guarantees

- Saver writes `{ Version, Metasets, Minima, Configs, FinalSellRemainder, SelectedConfigIndex? }` (via `buildHsfcPayload`) and downloads `*.hsfc`. When no config is explicitly selected, the last config index is saved by convention so loaders can preserve intent.
- Loader (`readHsfcFile`) accepts the readable HSFC schema and preserves each merged `substats` entry (`{ stat, fixed?, rollBounds? }`). `substatRollBounds.min`/`max` stay clamped to valid ranges (`min` 0..5, `max` 0..4) and wildcard flags remain intact. Legacy payloads that still provide `fixedSubstats`/`substatRollBounds` are converted inside `hsfcIO` so the rest of the app only deals with the new shape.
- Copy All mirrors the saver payload (including `SelectedConfigIndex`) to enable full round-trip via copy/paste.
- Sellfile export context menu: right-click `Export RSL Helper Sellfile` to open advanced options. `Export deduped RSL Helper Sellfile` runs a one-off dedupe pass that merges identical keep rules and removes dominated variants. `Export deduped by default` persists the behavior (key `sellfileCreator.sellfile.dedupDefault.v1`); when enabled, both downloads and push exports write the deduped payload. `Omit disabled rules when exporting` drops rules whose `Use` flag is `false` from downloads and push exports, and persists via `sellfileCreator.sellfile.omitDisabled.v1`.

## Behavioral Details

- Min vs Roll Upper Limit exclusivity: The builder now enforces mutual exclusivity; toggling one clears the other. HSFC persists only the active choice (`min`, `max`, or `any`).
- Roll Upper Limit enforcement: Rule generation filters distributions that exceed a per-substat `max`. A `max = 0` enforces “no rolls” on that substat.
- Auto resolution: Auto now keys strictly off `min ≥ 1` across selected substats; star and the Roll Upper Limit are ignored for Auto.
- Rank Any uses 6★ baseline: When `rankCode = 0` (Any), base substat targets map to the 6★ bucket for threshold generation (conservative default).
- Rarity ranges (≥): Conservative lower-bound behavior. `rollLevelsForRarityCode` maps `≥ Common..≥ Epic (6..9)` to the lower bound’s schedule (Common/Uncommon/Rare/Epic), and `≥ Legendary (16)` to Legendary. `rarityIncludesMythical` no longer assumes Mythical for any `≥` range; only exact Mythical (15) and `≤ Mythical (14)` imply the Mythical pre-roll.
- Any rarity baseline check: For the “how many substats exist” feasibility pass, `Any` is treated like `≥ Legendary` (no additions). Mythical pre-roll is still not assumed unless Σ mins or aggregate min equals 5.
- Rarity label parsing: HSFC normalize accepts human-readable `Rarity` strings (e.g. `"≥ Epic"`, `"Legendary"`, `"Any"`) and maps them to canonical codes. Numeric `rarityCode` is also accepted; `rarityExact` is no longer supported.
- Metaset name resolution on paste: `parseConfigsFromText(text, metasets)` resolves `artifactMetaSetNames` against the caller-provided current metasets. For full HSFC objects, `parseHsfcObject` resolves names against embedded `Metasets`; if absent, falls back to the app’s current metasets (`prev.metasets`). No default metasets are injected implicitly.
- Per-config pruning: Obsolete elimination now runs per config before merging, so preview table counts match the builder’s chip count. Cross-config overlaps remain visible for auditability.
- Obsolete comparator: Compares substats by the same StatVariant and raw Value for the same operator (no normalization to rolls). Tie-break prefers earlier rule indices within a config when values are equal.

## File Import UX

- Global drop target: The entire app window accepts file drops. Local dropzones were removed to reduce friction. Implemented via `useFileDragDrop` + `FileDragOverlay`.
- Overlay on file drag: A full-screen, non-interactive overlay appears on real file drags, indicating that `.hsfc` (configs + metasets), `.hsf` (sellfile), and `.db` (gear database) are accepted. Overlay uses `pointer-events: none` so it never blocks the actual drop.
- Routing by extension: Drops are dispatched by filename extension — `.hsfc` → HSFC loader (`readHsfcFile`), `.hsf` → HSF loader (`readHsfFile`), `.db` → gear importer (`importGearDatabaseFromFile`). Unknown extensions trigger the shared “file format” dialog so users know the payload was rejected.
- Load triggers: The `Load RSL Helper Sellfile` button follows the same flow as drag & drop, so it accepts `.hsf` for base merges and `.db` gear dumps for the Rule Tester.
- Error handling: Invalid or unreadable files (any of the accepted extensions) route through a single error dialog that spells out the supported formats so failures never disappear silently.
- Safety: Only intercept drags when `DataTransfer.types` includes `Files`; component drags (e.g., table column reorder) are unaffected.
- Load semantics:
  - `.hsfc`: Load/drag replaces the entire state (metasets, substatTargets, configs, final-sell, selection, note). No conflict merging on file load.
  - `.hsf`: Only the optional base Sellfile is replaced; builder configs remain untouched so merges stay deterministic.
  - `.db`: Gear rows are queued into the Rule Tester queue (and the preview auto-switches to the tester grid) without forcing the Logic Hub dialog open or mutating builder/export state. Manual/custom tester entries are left untouched so ad-hoc examples survive repeated imports regardless of whether the DB came from drag & drop, the picker, or the CLI command. Invalid DBs surface the same file-format dialog mentioned above.
    - The SQL.js WASM bundle is baked into the release as a data URI (`__SQL_JS_WASM_INLINE__`) so this workflow keeps working even when contributors open `dist/index.html` via `file://` with no dev server.

## HSFC Global Note

- Schema: HSFC may include an optional root-level `Note: string` with Markdown content.
- Load: When an HSFC with `Note` is loaded, a modal dialog opens automatically (view-only). The dialog can also be opened via the always-visible note button in the HSFC controls row: `Add Note…` when empty, `Note…` when populated (opens in view mode).
- Close: The dialog schedules its dismissal on the next animation frame; if a new note opens immediately after a close request (common during HSFC imports), the pending close is cancelled so the modal overlay never lingers.
- Edit: The dialog uses an embedded Markdown editor (`@uiw/react-md-editor`) with sanitized previews (`rehype-sanitize`). The editor lives in `src/components/NoteDialog.tsx`.
- Questionnaire markers: HTML comments inside the note can render interactive question blocks in the read-only view. Markers can be inline or multi-line; whitespace is optional.
  - Syntax (single): `<!-- q:single "Prompt" [* "Yes", tag1, tag2] ["No", -tag1] -->`.
  - Syntax (multi): `<!-- q:multi "Prompt" [* "Option", tag1] ["Other", tag2] -->`.
  - `*` before the label marks the default selection. `-tag` removes that tag from the active set. Whitespace is optional.
  - Prompt references: Wrap option labels in backticks to render them highlighted (e.g., ``Answering `Yes` will...``). Use numeric references like `` `\1` `` (1-based) to inject the Nth option label. Prompts accept literal newlines or `\n` escapes for line breaks.
  - Questions are evaluated top-to-bottom; later answers can override tags from earlier ones.
- Apply tags: The Note dialog exposes `Apply Questionnaire Tags`, which confirms and then enables/disables configs whose `Tags` intersect the active tag set. Untagged configs and separators are untouched.
- Session-only answers: Questionnaire answers are stored in autosave/session state only; HSFC exports never include them.
- Save/Copy: If a Note exists (non-empty), HSFC exports and “Copy all Configs” include it.
- Paste semantics: Pasting HSFC content (via context menu or manual paste) only overwrites the current note if the current note is empty. Loading a file always overwrites the current note.
- Metaset conflicts on paste (Copy/Paste only): identical value (same sets) keeps current ID and remaps pasted references. If the same ID has different sets, a single dialog offers: Keep current, Use pasted, or Keep both (new ID for pasted). Unknown pasted metaset IDs create hidden placeholders with generated names so chips never show raw IDs.
- Dependencies: `@uiw/react-md-editor`, `@uiw/react-markdown-preview`, and `rehype-sanitize`.

## Rule Tester

- Purpose: Gear editing lives in the Logic Hub Gear dialog (open via the `Gear…` button next to the preview toggle); it lets users build “what if” gear, paste manual stats, or import `.db` files without leaving the builder. The Rule Tester preview (the grid on the main screen) consumes that shared queue to evaluate which rule would keep or sell each artifact under “first match wins”.
- Surfaces: The Sellfile Preview header exposes two related controls:
- `Rule Tester` preview toggle — switches the main preview between the default HSF rule rows and the gear grid (this toggle is what “Rule Tester mode” refers to).
- The tester grid defaults to grouping artifacts by set and accessories by faction + set. The Sort popover’s Grouping controls can switch to accessories-by-faction (artifacts flat), split artifacts vs accessories, or fully flat (no headers); grouping changes only apply while substat sort is active, otherwise the default grouping returns. Non-default grouping uses a single global substat sort order (when substat sorting is active) instead of re-sorting inside each section. Each card dedicates three columns to the schematic preview (slot glyph + set badge + overlays), the main/substat stack, and the matching-config summary (keep/sell glyph, primary rule/config chip, plus additional matching configs capped with a `+N` chip). Virtualization runs at both the group and card level so collapsed groups skip rendering and large inventories stay responsive.
- Card hydration runs through a reveal queue that flushes within a ~6 ms frame budget, prioritizes on-screen cards, prunes entries more than ~4,000 px away whenever the queue passes roughly 70 items, and drains the backlog whenever scrolling pauses for ~200 ms; rows that fall outside the window simply re-enqueue when the user scrolls back toward them, which keeps reverse scrolling responsive without throwing away recent warm-up work.
- Right-click anywhere inside the tester grid scroll container opens the grid context menu (hinted via `useContextMenuHint('testerGridContextMenu')`). The menu mirrors the preview header controls: toggle stat-color text + Manage Colors, cycle the color-blind palette, flip between `4`/`5` column layouts (default `5` at ≥ `sm`, and the button text simply shows the active number), show/hide the first-match and other-match rows, and optionally display champion portraits for vault/collection gear. These preferences persist through `src/state/testerGridPreferences.ts`, so grid layout changes (including the champ-icon toggle) survive reloads.
- Champion portraits: when a gear entry references a champion (imported collection or vault gear) and the “Show champion icons” preference is enabled, the card swaps the slot glyph for the champion image. Collection items show only the portrait, while vault items add the vault glyph to the right of the portrait, aligned under the gear’s level badge. If no known portrait exists (or the preference is off) the card reverts to the original slot glyph + source icon combo so the grid never loses the origin indicator.
- Fresh sessions start empty — no sample gear is auto-added. Import RSL Helper DB dumps, paste gear, or add custom items via the dialog to populate the grid.
- Ctrl/Cmd+clicking a top-level accordion header (artifact set or faction) collapses/expands every group at once, while the same gesture on a faction’s set accordion only affects that faction’s sets. A normal click still toggles just the targeted accordion.
- `Gear...` button — opens the Logic Hub dialog on the Gear tab (the Gear dialog) where gear can be edited, pasted, or imported; edits are reflected immediately in the preview toggle mode without reopening the dialog.
- The Gear tab only renders custom entries; imported inventory/equipped/inbox rows stay visible in the preview and can be batch-deleted per-source via the new toolbar buttons. A persistent `Add custom gear` action lives in the tab footer so users can rebuild lists from an empty state.
- Preview toggle persistence: The Sellfile Preview / Rule Tester mode toggle saves its last selection to `localStorage` (defaulting to Sellfile Preview) so reloading the app restores the same table.
- Rule-source chips: Final Sell matches render a warning-colored `Final Sell` chip, and Keep Unique matches render a green `Keep Uniques` chip; both cases bypass the regular HSF rule label so the tester grid immediately calls out the special keep path.
- Last-used filter: the tester filter drawer adds a `Last used` section with quick presets (`Never used`, `≤7d`, `≤30d`, `≤90d`, `>90d`) plus an “Advanced range…” popover for custom day ranges. Presets act as toggles that combine as a union (only one `≤N` bucket remains at a time so redundant mixes like `≤90d` + `≤30d` collapse), and the custom slider also unions with the presets so users can mix precise ranges with the coarse buckets. Timestamp-free gear is controlled entirely by the `Never used` preset—there is no longer a custom “include unknown” switch—and the active state still contributes to the global “filters on” indicator.
- Tester cards surface everything inline: slot glyph + rarity-bordered frame with `8px` corners, overlapping rank/ascension stars, 16px keep/sell + reroll glyphs, level badges, set badge tooltip (includes the set bonus stats), main stat + ascension rendered inline in 4-column mode (the ascension line drops below the main stat in the tighter 5-column layout), substats with glyph deltas/roll badges and Mythical underline, the matching rule/config chip (button jumps to the builder rule), and a single-line row of additional matching configs capped with a `+N` chip. Source/faction info remains below the icon stack, matching the Sellfile preview cues, and leaf accordions add padding so edge cards do not clip the borders.
- The row below the icon stack now renders source glyph chips instead of text so the inventory/vault/collection distinction is clearer. Manual entries use the build glyph, collection rows use `PersonOutline`, the vault glyph reuses the inventory icon, inbox items keep `MailOutline`, and inventory entries render the tooltip/aria label without a glyph. The Source chip line is driven by `src/lib/testerPreviewFormatting.ts` + `SOURCE_ICON_MAP` in `src/components/TesterItemsGrid.tsx`, and the tooltips still show translated labels for screen readers.
- Preview sorting: Tester cards sort armor pieces before accessories, then by set (in-game numeric order), slot (`compareArtifactTypes`), rank (6★→1★), rarity (Mythical→Common), and ascension tier (highest first) so custom gear stays grouped predictably with game metadata.
- Rules source: Evaluates against the effective rules array provided by the preview (merged base + custom when present). Disabled rules never match.
- Match freeze: `testerMatchFreeze` hides the imported gear whenever we rebuild matches so the grid only renders steady-state results. Autosave restores that also rehydrate configs/metasets keep a single freeze alive across both queue passes (initial rehydration plus the rules-triggered rebuild) by tracking the final tester build id; users now see one hidden → match transition after everything commits instead of two quick flashes. While a freeze is active both the preview grid and Keep Uniques dialog pass `suppressMatchDetails` to `TesterItemsGrid`, which now leaves the first/other match rows visible but dims the chips + outcome badge and disables their jump handlers so testers remember the previous match without accidentally drilling into stale data.
- Evaluator: `src/lib/ruleEval.ts` exposes `evaluateFirst(rules, item)` (pure). Uses shared rank/rarity coverage helpers from `src/lib/hsfTypes.ts`.
- Autosave: Session persists under `AUTOSAVE_TESTER_KEY`, stores the gear list as a gzip/base64 payload (plus a saved timestamp), and is offered as an optional checkbox inside the global Restore dialog. The queue only replaces the current tester state when the user selects the checkbox; otherwise the saved copy remains in storage until they opt in or overwrite it with a newer autosave. Autosave activates automatically once the gear deviates from the initial baseline (imports, restores, edits) and stays active even if the Gear tab is closed; opening the Logic Hub dialog also primes autosave immediately.
- Gear resets (`Reset to defaults → Gear`) route through the same `beginTesterMatchReset('gearDb')` helper as DB imports so the tester-match worker cancels in-flight builds, clears Keep Unique detection, and emits a fresh snapshot before the grid re-renders an empty queue.
- State ownership: `App.tsx` holds the gear list via the helpers in `src/lib/ruleTesterSession.ts`; the dialog receives `[items, setItems]` plus the shared row-id allocator so edits flow directly into the preview without extra effects.
- Gear entry shape (readable summary):
  - Slot (`ArtifactTypeId`), Set (`ArtifactSetId`), Rank (`1..6`), Rarity (`1..6` Common..Mythical), Level (`LevelMilestone` entries 0/4/8/12/16), Faction (`FactionId` for accessories), Main (`StatVariant`), Substats as absolute values (variant→value) preserving user order.
- The count of available substats derives from rarity and level; values clamp to per-rank substat targets from the shared `SubstatTargetTable`. Substats equal to the selected main or not allowed by slot are filtered out. Missing substats are auto-filled from allowed candidates up to that availability count.
- Sentinel IDs: `ACCESSORY_NO_SET_ID = -99` means “None — Only accessories” and is shared by the Rule Tester and Final Sell remainder; `TESTER_ANY_SLOT_ID = 0` means “Any slot” and only matches rules that do not restrict slots.
- Sets dropdown: each gear entry owns its menu state (`setsMenuOpenIdx`); only the active card’s `Select` is forced open, and the menu anchor is cleared on the next animation frame after close. This keeps armor/accessory filtering intact, closes immediately after choosing a set (including the accessory “No set” sentinel), and prevents the anchored menu from jumping horizontally when reopening the selector.
- Compact summary chips always render accessory faction icons with a tooltip so the tester snapshot mirrors the Sellfile Preview; the global “Factions as icons” preference does not hide them.
- The combined rule/config chip displays the config faction icon (when set) under the same preference, matching the Sellfile Preview header behavior.
- Constants: Layout sizing is centralized in `src/lib/constants.ts` (`TESTER_*` widths and heights, result row minimum height) to keep the dialog compact and stable across locales.
