Roll Filter Popover – ASCII Wireframe
=====================================

Context: the Rule Tester roll filter trades the ≥ / = / ≤ comparators for a
compact “pick the roll counts you care about” UI. Each row exposes the six roll
counts (`Ø`, `1`, `2`, `3`, `4`, `5`) as toggleable badges so users can pick any
number of discrete values (e.g., {2, 4, 5}). The backend now stores those sets
directly, so the filter semantics stay in sync with what the UI renders.

Legend
------
- `[X]` close button supplied by `ContextMenuPaper`
- `(•)` filled toggle (selected) / `( )` unselected toggle
- `○` = unselected roll count, `●` = selected roll count
- Stat summaries show braces (`SPD {2,4}`) in the footer/aria copy instead of inline chips
- Wildcard row works the same way but applies to any/selected stats depending on mode

Key behavioral notes
--------------------
1. Expressiveness now mirrors discrete sets; the backend stores the same array so predicates
   can test membership directly (no comparators to reconstruct).
2. UI footprint stays tiny—no numeric inputs, min/max rows, or comparator toggles—while the
   All/None buttons provide quick shortcuts.
3. Non-glyphable stats still stay hidden; every glyphable stat is visible simultaneously.
4. Summary copy mirrors the new semantics (`{…}`) so users understand they’re selecting exact
   counts rather than ranges, and the Rolls chip’s aria-label reuses the same string.
