## 4. New technical debt introduced since v0.9.8
- `src/lib/importers/gearDbImporter.ts:118-190` still reads entire tables on the main thread, looping through `while (stmt.step())` and only `await tick()` every 250 rows. Normalizing thousands of artifacts (the sample DB is ~7k rows) still risks janking the UI, and we have no worker/streaming fallback for loading `.db` files. Consider moving the normalization into a dedicated worker or breaking it into smaller async batches with more aggressive yielding.

## 4. Technical debt introduced since v0.9.8
- `src/components/TesterItemsGrid.tsx:302-420,1878-1910` relies on custom virtualization math with a pile of magic constants but no automated coverage. Any tweak to card padding, number formatting, or champion icon sizing can silently desynchronize the cached heights and the actual DOM, leading to blank holes or overlapping cards. We need deterministic storybook/tests that assert the virtualization window before touching the layout, or we should switch to a proven virtualization library.
- `src/hooks/useTesterMatchWorker.ts:1-140` duplicates the entire `evaluateMatchesByConfig` flow, queues promises manually, and never tests the worker handshake. There’s no guard against stale evaluate responses resolving after a new configure (the results are handed straight back to callers), and any worker-side exception only surfaces via `console.error`. We should add unit tests covering configure/evaluate sequencing and consider tagging responses with a configuration version so old results are discarded.
- `src/lib/iconMaps/championIconMap.ts:1-21` now `import.meta.glob`s every `.webp` under `ico/champs/` with `eager: true`, pulling hundreds of champion portraits into the main bundle even when the tester grid never shows them. This inflates initial load and memory, especially in browsers without compression caching. We should either lazy-load per-ID (defer to `import.meta.glob` dynamic imports) or ship a CDN-backed sprite instead of bundling everything eagerly.
