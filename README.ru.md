# RSL Helper Sellfile Creator

Создавайте, просматривайте и экспортируйте правила продажи для RSL Helper через понятный интерфейс.

> Независимый фанатский проект. Не связан с Plarium, Raid: Shadow Legends или RSL Helper. Все упомянутые товарные знаки принадлежат их владельцам.

## Возможности
- Создание и сохранение правил: собирайте конфигурации и храните собственную библиотеку.
- Просмотр Sellfile: проверяйте сгенерированные правила — с текущей sellfile или без неё.
- Совместный просмотр (опционально): перетащите `.hsf` в приложение, чтобы увидеть его вместе с новыми правилами. Можно также добавить файл конфигураций (`.hsfc`). Оверлей подскажет допустимые форматы.
- Метасеты: объединяйте наборы экипировки (например, Скорость + Восприятие) и переиспользуйте их в нескольких правилах.
- Экспорт одним кликом: выгружайте HSF (sellfile для RSL Helper), готовый к загрузке в RSL Helper.

## Как использовать

### Файл конфигураций
- HSFC (`.hsfc`): проектный файл приложения. Это «сохранение», которое можно загрузить или передать другим. RSL Helper не читает HSFC напрямую.
- HSF (`.hsf`): sellfile для RSL Helper. Экспортируйте его в приложении, затем загрузите в RSL Helper.
- Имя файла по умолчанию: `SellfileCreatorRules_ГГГГММДД_ЧЧММ.hsfc`.

### Конструктор конфигураций
- Заполните поля конструктора и дайте конфигурации понятное имя.
- Нажмите «Добавить как новую конфигу», чтобы сохранить её. Затем выберите конфигурацию в списке под конструктором, внесите правки и нажмите «Обновить выбранную конфигу».
- Загрузка/сохранение: кнопки «Загрузить конфиги» и «Сохранить конфиги» позволяют переиспользовать ваши правила. Они сохраняют всё, что необходимо для восстановления предпросмотра.
- Примечание: «Добавить примечание» (или «Редактировать примечание») прикрепляет заметку к файлу конфигураций. При загрузке HSFC с заметкой она отображается автоматически.

### Структура конструктора (сверху вниз)
- Действие: Оставить или Продать, плюс переключатель «Включено».
  - «Включено» определяет, будут ли правила этой конфигурации активны. Если выключено, правила экспортируются, но игнорируются RSL Helper. В предпросмотре такие строки перечёркнуты белой линией, а подпись конфигурации показывает зачёркнутый текст «Оставить/Продать».
- Ранг, Редкость, Фракция, Уровни.
  - Фракция (опционально) относится только к аксессуарам (Кольцо, Амулет, Знамя).
  - Уровни: выберите минимальный и максимальный уровни из +0, +4, +8, +12, +16. Для каждого промежуточного уровня генерируются правила.
  - Редкость = Авто (рекомендуется): выбирает минимальную редкость, при которой условия выполняются в заданном диапазоне уровней.
    - Нет минимального количества проков? Авто оставляет правила широкими и совместимыми со всеми редкостями.
    - Требуются 1/2/3/4 доп. характеристик на +0? Авто убедится, что редкость стартует с нужным количеством (1 → ≥ Необычный, 2 → ≥ Редкий, 3 → ≥ Эпический, 4 → ≥ Легендарный).
    - Нужны конкретные количества проков (например, «минимум 3 проков»)? Авто выберет редкость, способную добиться этого к +16. Для 5 проков выбирается Мифический.
    - Чип «Авто ≥» (рядом с Редкостью): задаёт нижний предел для Авто и при режиме Late добавляет дополнительные строки с «≥» на нужных уровнях.
      - Последовательность: Необычный → Редкий → Эпический. «Авто ≥ Редкий» означает, что Авто не опустится ниже ≥ Редкого.
      - Наилучший результат с Late и заданными минимальными проками. Если чип неактивен, рядом отображается «Auto + Late» с диагональной чертой.
      - Пример: Знамя со скоростью и ATK%, ATK% требует 2 проков. Поставьте Редкость = Авто, режим = Late и Авто ≥ Эпический.
        - Получите строки для Эпического уровня в диапазоне и дополнительные строки ≥ Легендарный на +8/+12 (для легендарки последний прок часто выпадает на +16).
        - Итог: Эпический уровень остаётся строгим, легендарный — честным; ни один предмет не отфильтровывается только из-за более высокой редкости.
    - Присутствие до +16: если текущая редкость ещё не может иметь требуемое число характеристик, правило использует максимум, доступный на этом уровне. На +16 применяются ваши целевые значения.

- Основная характеристика и доп. характеристики – три одинаковые строки переключателей:
  1) Any
  2) HP, HP%, ATK, ATK%, DEF, DEF%
  3) SPD, RES, ACC, CR%, CDMG%
  - Основная характеристика поддерживает множественный выбор. Пусто = Any. Несколько значений создают по одному правилу на каждую основную характеристику.
  - «Any» — быстрый сброс. Для доп. характеристик «Any» равнозначно пустому выбору; как только вы выбираете конкретные статы, Any отключается.
  - Доп. характеристики имеют три состояния: клик = выбрать; повторный клик = зафиксировать (🔒); ещё один клик = убрать. Зафиксированные характеристики всегда попадают в правило. Общее количество целевых статов = max(Обязательно, Зафиксировано), максимум 4.
  - Индикатор проков: маленький круг на каждом выбранном стате.
    - ЛКМ = увеличить. ПКМ = уменьшить.
    - Джокер (★): проки могут распределяться как угодно по этому стату.
    - ЛКМ по ★ задаёт минимум проков (зелёный): 0 → 1 → 2 → 3 → 4 → 5 → ★.
    - ПКМ по ★ задаёт верхний предел (красный): 0 → 1 → 2 → 3 → 4 → ★. Предел 0 запрещает проки.
    - Минимум и Предел взаимоисключают друг друга.
- Обязательные доп. характеристики – блок справа. Определяет, сколько выбранных статов должно быть на предмете. Зафиксированные статы всегда идут в зачёт.
- Выбор сетов/метасетов: чипы под секцией статов показывают выбранные сеты и метасеты.
- Режим Early/Late:
  - Early: на каждом уровне формируются комбинации, которые остаются валидными до конечной цели. Джокеры + минимальное количество проков создают все возможные распределения на каждом уровне. Ограничения соблюдаются.
  - Late: заставляет предмет удовлетворять лишь необходимым требованиям на конкретном уровне, сохраняя возможность достичь цели на +16. Для джокеров + минимального количества проков Late показывает присутствие на ранних уровнях и применяет минимальные распределения на +16. Для индивидуальных минимумов по статам Late выдаёт минимальные значения на каждый уровень.

Пример: Early (2 стата) — SPD мин = 2, CR% мин = 1 (уровни 0..16)
- +0: SPD ≥ 5, CR ≥ 5
- +4: [10,5] и [5,10]
- +8: [15,5], [10,10], [5,15]
- +12/+16: [15,10]

Пример: Late (2 стата) — SPD мин = 2, CR% мин = 1 (0..16)
- +0/+4: [5,5]
- +8: [10,5] или [5,10]
- +12: [15,5] или [10,10]
- +16: [15,10]

Пример: Early (3 стата) — SPD мин = 2, CR% мин = 1, CDMG% произвольный, Обязательно = 3
- +0: [SPD, CR, CDMG] ≥ [5,5,5]
- +4: комбинации с одним проком: [10,5,5], [5,10,5], [5,5,10]
- +8: комбинации с двумя проками (учитывая лимиты)
- +12/+16: [15,10,5]

Пример: Late (3 стата) — SPD мин = 2, CR% мин = 1, CDMG% произвольный, Обязательно = 3
- +0/+4: [5,5,5]
- +8: [10,5,5] или [5,10,5]
- +12: [15,5,5] или [10,10,5]
- +16: [15,10,5]

Совет: используйте верхние пределы, чтобы запрещать проки в стат. От ★ нажмите ПКМ и выставьте 0. Так CDMG% останется базовым, а SPD/CR получат проки.

Пример: Один стат фиксируем, два требуем
- Выберите SPD, HP, ATK. Дважды кликните по SPD, чтобы зафиксировать (🔒).
- Обязательных статов = 2.
- Результат: правила содержат SPD+HP и SPD+ATK, но не HP+ATK без SPD.

Пример: Фокус на трёх статах, запрет на четвёртом
- Цель: оставлять предметы со SPD, CR%, CDMG% и одним из HP%/ATK%/DEF%, но без проков в четвёртый стат.
- Выберите SPD, CR%, CDMG%, HP%, ATK%, DEF%.
- Обязательных статов = 4.
- Индикаторы:
  - От ★, ЛКМ (минимум): выставьте SPD/CR%/CDMG% на нужные минимумы (например, по 1).
  - От ★, ПКМ (предел): поставьте HP%/ATK%/DEF% в 0.
- Итог: четвёртый стат может меняться, но проков не получает; проки достаются SPD/CR%/CDMG%.

Пример: Early с джокером (только выбранные статы)
- Выберите SPD и ACC.
- Индикаторы: SPD мин = 2; ACC = ★.
- Обязательных статов: Auto (2).
- Уровни: +0..+16.
- Результат: Early показывает предметы, которые к +16 могут получить SPD(2) (строки, где прок получил SPD или ACC). Как только два прокa SPD становятся возможны, появляется строка с минимумом.

Пример: Сумма проков с джокерами (2 стата)
- Выберите SPD и ACC, оба поставьте на ★.
- Обязательных статов: 2. Мин. проков: 1.
- Early:
  - +4/+8/+12/+16: две строки — SPD ≥ 10, ACC ≥ 9 и SPD ≥ 5, ACC ≥ 18 (минимальные распределения, стабильны).
- Late:
  - +0/+4/+8/+12: только присутствие (минимум сейчас = 0); +16: две строки выше. При большем минимуме Late вводит минимальные распределения на нужных уровнях.

## Сохранение и устранение неисправностей
- Для продвинутых пользователей: особенности хранения данных и работы буфера обмена.
- Открытие `index.html` напрямую (file://) часто ограничивает хранилище сайта:
  - Автосохранение (конфиги, метасеты, минимумы) и настройки таблиц/цветов могут не сохраняться.
  - Копирование в буфер обмена может блокироваться; тогда приложение показывает альтернативный диалог.
- Чтобы гарантировать сохранность, запускайте через http(s) (например, dev-сервер Vite или статический хостинг).
- Диалог восстановления не появляется? Или ещё нет автосохранения, или вы работаете через file:// без постоянного localStorage.
- Колонки сбрасываются? Режим инкогнито/гостевой или очистка данных стирают сохранённые настройки.
- Палитры для дальтоников: ПКМ по заголовку предпросмотра → «Палитра для дальтоников». Доступно:
  - Normal: стандартные цвета успеха/предупреждения/ошибки.
  - Okabe–Ito: палитра для дейтеранопии/протанопии (синий/оранжевый/алый).
  - Tritan: палитра для тританопии (зелёный/оранжевый/пурпурный).
- Выбор сохраняется локально и применяется ко всем зонам, где используются эти цвета.
