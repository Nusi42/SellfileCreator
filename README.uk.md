# RSL Helper Sellfile Creator

Створюйте, переглядайте та експортуйте правила продажу для RSL Helper за допомогою зручного інтерфейсу.

> Це незалежний фанатський проєкт. Не має відношення до Plarium, Raid: Shadow Legends чи RSL Helper. Усі торгові марки належать їхнім власникам.

## Можливості
- Створення та збереження правил: збирайте конфігурації й підтримуйте власну бібліотеку.
- Попередній перегляд Sellfile: перевіряйте згенеровані правила — з поточним sellfile або без нього.
- Комбінований перегляд (за бажанням): перетягніть `.hsf` у застосунок, щоб подивитися його разом із правилами. Можна додати й файл конфігурацій (`.hsfc`). Оверлей підкаже, які файли приймаються.
- Метасети: групуйте набори екіпіровки (наприклад, Швидкість + Сприйняття) та використовуйте їх у різних правилах.
- Експорт в один клік: отримаєте HSF (sellfile для RSL Helper), готовий до завантаження в RSL Helper.

## Як користуватися

### Файл конфігурацій
- HSFC (`.hsfc`): проєктний файл застосунку. Це «збереження», яке можна відкрити або передати комусь. RSL Helper не читає HSFC напряму.
- HSF (`.hsf`): sellfile для RSL Helper. Експортуйте його у застосунку, а потім завантажте в RSL Helper.
- Типова назва під час збереження: `SellfileCreatorRules_РРРРММДД_ГГХХ.hsfc`.

### Конструктор конфігурацій
- Заповніть поля конструктора та задайте конфігурації виразну назву.
- Натисніть «Додати як нову конфіг», щоб зберегти. Потім оберіть конфігурацію в списку під конструктором, внесіть зміни і натисніть «Оновити вибрану конфіг».
- Завантаження/збереження: кнопки «Завантажити конфіги» та «Зберегти конфіги» дозволяють повторно використовувати правила. Вони містять усе, що потрібно для відновлення попереднього перегляду.
- Примітка: «Додати примітку» (або «Редагувати примітку») додає текст до файлу конфігурацій. Після завантаження HSFC з приміткою її буде показано автоматично.

### Структура конструктора (зверху вниз)
- Дія: Залишити чи Продати та перемикач «Увімкнено».
  - «Увімкнено» визначає, чи будуть правила активними. Якщо вимкнено, правила експортуються, але RSL Helper їх ігнорує. У попередньому перегляді такі рядки мають біле перекреслення, а підпис конфігурації показує закреслений текст «Залишити/Продати».
- Ранг, Рідкість, Фракція, Рівні.
  - Фракція (необов’язково) застосовується лише до аксесуарів (Перстень, Амулет, Стяг).
  - Рівні: оберіть мінімальний та максимальний рівні з +0, +4, +8, +12, +16. Правила генеруються для кожного кроку в цьому діапазоні.
  - Рідкість = Авто (рекомендовано): обирає найнижчу рідкість, яка дозволяє виконати ваші вимоги в заданому діапазоні рівнів.
    - Немає мінімальної кількості проків? Авто залишає правила широкими і сумісними з усіма рідкостями.
    - Вимагаєте 1/2/3/4 субстати на +0? Авто гарантує, що рідкість стартує з потрібною кількістю (1 → ≥ Незвична, 2 → ≥ Рідкісна, 3 → ≥ Епічна, 4 → ≥ Легендарна).
    - Вимагаєте суму проків (наприклад «мінімум 3 проки»)? Авто вибере рідкість, здатну досягти цієї кількості на +16. Для 5 проків обирається Міфічна.
    - Чип «Авто ≥» (поряд із Рідкістю): задає нижню межу для Авто і разом із Late додає додаткові рядки «≥» на відповідних рівнях.
      - Порядок: Незвична → Рідкісна → Епічна. «Авто ≥ Рідкісна» означає, що Авто не опускається нижче ≥ Рідкісної.
      - Найкраще працює з режимом Late і заданими мінімальними проками. Якщо чип неактивний, бачите «Auto + Late» із діагональною рискою.
      - Приклад: Стяг із SPD та ATK%, а ATK% потребує 2 проки. Встановіть Рідкість = Авто, Режим = Late, Авто ≥ Епічна.
        - Отримаєте епічні рядки в усьому діапазоні та додаткові рядки ≥ Легендарна на +8/+12 (останній легендарний прок часто на +16).
        - Результат: епічний рівень залишається чітким, легендарний — справедливим; жоден предмет не відсіюється через вищу рідкість.
    - Присутність до +16: якщо рідкість ще не дозволяє потрібну кількість субстатів, правило використовує доступний максимум на поточному рівні. На +16 застосовуються ваші цільові значення.

- Головний стат і субстати – три однакові ряди перемикачів:
  1) Any
  2) HP, HP%, ATK, ATK%, DEF, DEF%
  3) SPD, RES, ACC, CR%, CDMG%
  - Головний стат допускає кілька виборів. Без вибору = Any. Кілька значень генерують по правилу для кожного головного стата.
  - «Any» — швидкий скидання. Для субстатів «Any» означає порожній вибір; щойно ви обираєте конкретні стати, Any вимикається.
  - Субстати мають три стани: клік = вибрати; повторний клік = зафіксувати (🔒); ще один клік = прибрати. Фіксовані субстати завжди потрапляють до правила. Загальна ціль = max(Обов’язково, Зафіксовано), максимум 4.
  - Індикатор проків: невелике коло на кожному вибраному статі.
    - ЛКМ = збільшити. ПКМ = зменшити.
    - Вайлдкард (★): проки можуть розподілятися довільно на цьому статі.
    - ЛКМ по ★ задає мінімум проків (зелений): 0 → 1 → 2 → 3 → 4 → 5 → ★.
    - ПКМ по ★ задає верхню межу (червоний): 0 → 1 → 2 → 3 → 4 → ★. Межа 0 забороняє проки.
    - Мінімум і Межа взаємовиключні.
- Обов’язкові субстати – блок праворуч. Визначає, скільки вибраних субстатів обов’язково має містити предмет. Зафіксовані стати завжди враховуються.
- Вибір сетів/метасетів: чипи під секцією субстатів показують активні сети й метасети.
- Режим Early/Late:
  - Early: на кожному рівні будує комбінації, що залишаються валідними до кінцевої мети. Вайлдкарди + мінімальна кількість проків дають усі можливі розподіли на кожному рівні. Межі зберігаються.
  - Late: вимагає лише необхідне на поточному рівні, зберігаючи можливість досягти цілі на +16. Для вайлдкард + мінімуму проків показує присутність на ранніх рівнях і застосовує мінімальні розподіли на +16. Для індивідуальних мінімумів генератор створює мінімальні значення на кожний рівень.

Приклад: Early (2 субстати) — SPD мін = 2, CR% мін = 1 (рівні 0..16)
- +0: SPD ≥ 5, CR ≥ 5
- +4: [10,5] та [5,10]
- +8: [15,5], [10,10], [5,15]
- +12/+16: [15,10]

Приклад: Late (2 субстати) — SPD мін = 2, CR% мін = 1 (0..16)
- +0/+4: [5,5]
- +8: [10,5] або [5,10]
- +12: [15,5] або [10,10]
- +16: [15,10]

Приклад: Early (3 субстати) — SPD мін = 2, CR% мін = 1, CDMG% довільний, Обов’язково = 3
- +0: [SPD, CR, CDMG] ≥ [5,5,5]
- +4: розподіли з одним проком: [10,5,5], [5,10,5], [5,5,10]
- +8: розподіли з двома проками (з урахуванням обмежень)
- +12/+16: [15,10,5]

Приклад: Late (3 субстати) — SPD мін = 2, CR% мін = 1, CDMG% довільний, Обов’язково = 3
- +0/+4: [5,5,5]
- +8: [10,5,5] або [5,10,5]
- +12: [15,5,5] або [10,10,5]
- +16: [15,10,5]

Порада: використовуйте верхні межі, щоб заборонити проки на статі. Від ★ натисніть ПКМ і встановіть 0. Так CDMG% залишиться базовим, а SPD/CR отримуватимуть проки.

Приклад: Фіксуємо один стат, вимагаємо два
- Оберіть SPD, HP, ATK. Двічі натисніть на SPD, щоб зафіксувати (🔒).
- Обов’язкові субстати = 2.
- Результат: правила містять SPD+HP і SPD+ATK, але не HP+ATK без SPD.

Приклад: Зосередити проки на 3 статах, заборонити четвертий
- Мета: залишати предмети зі SPD, CR%, CDMG% та одним з HP%/ATK%/DEF%, але без проків на четвертому статі.
- Оберіть SPD, CR%, CDMG%, HP%, ATK%, DEF%.
- Обов’язкові субстати = 4.
- Індикатори:
  - Від ★, ЛКМ (мінімум): задайте SPD/CR%/CDMG% потрібні мінімальні значення (наприклад, по 1).
  - Від ★, ПКМ (межа): встановіть HP%/ATK%/DEF% у 0.
- Результат: четвертий стат чергується між трьома, але без проків; SPD/CR%/CDMG% отримують проки.

Приклад: Early із вайлдкардом (лише вибрані субстати)
- Оберіть SPD та ACC.
- Індикатори: SPD мін = 2; ACC = ★.
- Обов’язкові субстати: Auto (2).
- Рівні: +0..+16.
- Результат: Early показує предмети, які можуть дістати SPD(2) до +16 (рядки, де SPD або ACC отримали прок). Коли можливі два проки в SPD, з’являється мінімальна рядок.

Приклад: Сума проків із вайлдкардами (2 субстати)
- Оберіть SPD та ACC, переведіть обидва у ★.
- Обов’язкові субстати: 2. Мінімум проків: 1.
- Early:
  - +4/+8/+12/+16: дві рядки — SPD ≥ 10, ACC ≥ 9 та SPD ≥ 5, ACC ≥ 18 (мінімальні розподіли, стабільні).
- Late:
  - +0/+4/+8/+12: лише присутність (поточний мінімум = 0); +16: дві рядки вище. За вищих мінімумів Late застосовує мінімальні розподіли на відповідних рівнях.

## Примітки для учасників

- Переклади: Архіви релізів містять шаблони локалізації в каталозі `i18n/` (наприклад, `i18n/en-US.l10n.json`, `i18n/de-DE.l10n.json`, `i18n/fr-FR.l10n.json`, `i18n/es-ES.l10n.json`, `i18n/pt-PT.l10n.json`, а також заготовки `i18n/ru-RU.l10n.json`, `i18n/uk-UA.l10n.json`, `i18n/tr-TR.l10n.json`).
- Редагування й тест: Відкрийте застосунок і перетягніть свій змінений файл `*.l10n.json`, щоб застосувати його одразу для поточної сесії (жодного встановлення не потрібно).
- Надсилання виправлень: Надсилайте оновлений JSON через pull request (краще) або додайте його до issue. Не змінюйте ключі; відсутні ключі показуються англійською.
- Вбудовані мови: Усі вбудовані мови зібрані в єдиний HTML-файл, тож застосунок працює офлайн. Ваші оновлення потраплять до наступного релізу.
